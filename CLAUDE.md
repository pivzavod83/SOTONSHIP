# Repository instructions

This project is an AI-assisted COBOL-to-Java paired defect-review workbench, with a local learned graph-feature defect pilot, optional coding-LLM review/program matching and independent bounded financial verification. The local detector failed held-out generalization; preserve and display that result. Work in `backend/`, `ml-engine/` and the optional `vscode-extension/` client, plus root documentation/configuration and provenance records in `data-sources/`. Keep `frontend/` empty except for `.gitkeep`.

## Required architecture

The API is NestJS + **Layered DDD + CQRS + MikroORM + PostgreSQL**. Never introduce TypeORM or replace CQRS with a controller/service/repository chain.

```
HTTP -> presentation/controllers (validated DTO)
     -> CommandBus / QueryBus -> application handler
     -> domain repository interface -> infrastructure repository
     -> infrastructure mapper -> module-root MikroORM persistence entity -> PostgreSQL
application handler -> presentation RTO -> HTTP
```

Apply this layout to `backend/src/modules/verification/` and `fx-rates/`:

| Location | Responsibility |
| --- | --- |
| `presentation/controllers`, `dto`, `rto` | HTTP, validation, Swagger, DTO input and RTO output; dispatch commands/queries. |
| `application/commands/handlers`, `queries/handlers`, `services` | Use cases; mutations are commands, reads are queries. Handlers orchestrate aggregates, repository ports and the ML bridge, publish events, and construct RTOs. |
| `domain/entities`, `value-objects`, `repositories`, `events`, `enums` | Pure TypeScript business model. No NestJS, MikroORM, database, subprocess or HTTP imports. |
| `infrastructure/repositories`, `mappers`, `ml-bridge` | MikroORM adapters, persistence/domain conversion and Python subprocess integration. |
| module-root `entities/*.entity.ts` | MikroORM PostgreSQL table declarations, separate from domain entities. |
| `backend/src/common/` | Exceptions/filter, translations, shared values/RTOs/pipes, migrations and seeders. |

Inject repository interfaces with explicit tokens such as `'IVerificationRepository'`. The infrastructure mapper is the conversion boundary between persistence and domain models. Discover compiled persistence models with `dist/**/entities/*.entity.js`, and use the matching TypeScript pattern during development. Preserve numeric FX rates as decimal strings. Never return persistence or domain entities directly from controllers.

`VerificationRun` holds sources, alignment/risk scores, baseline, proof status, graph, witnesses, scope and provenance. Commands run verification or apply a proposed patch. A patch can be saved only after fresh Z3 verification returns `UNSAT_PROVEN_SAFE`; preserve the original row on failed verification. Publishing a completion event does not imply that a run was proved safe.

Use explicit migrations and the idempotent initial seeder. Four precomputed rows make the list API useful immediately after setup; do not overwrite subsequently patched runs when reseeding.

## Engine and proof integrity

`POST /api/defect-reviews` and `GET /api/defect-reviews/status` use the separate read-only, layered `defect-detection/` module and shared bounded Python worker. `ml_engine.defect_detection` performs local NumPy inference with `defect_model_v1.json`; no API key, provider call, submitted-code execution, persistence or proof authority. Its statement/dependency graphs are heuristic features, not a trained GNN or compiler. Three trained classifier/ranker fold members are retained with no full refit. Exact source hashes and server-validated raw LF spans/excerpts bind `MODEL_HYPOTHESIS` findings. A low score or empty findings never means equivalence.

The synthetic detector uses the frozen `evaluation/synthetic-pilot/pilot-10-r3/` dataset: six training families/24 pairs, two validation families/eight pairs, two test families/eight pairs. Training preprocessing and localization supervision stay within each fitting fold; IDs, order, metadata, rationale, test outcomes and supplied alignments are not inference features. Settings were selected using training OOF and validation only; validation exploration is disclosed. Original uploads, data/split hashes, fold models, code snapshots and final evaluation remain immutable. No test-driven retuning: use a separately versioned experiment with test reuse disclosure if further work is requested.

The final frozen detector scored **1/8 correct (12.5%)**, precision 20%, recall 25%, F1 22.2% (TP1/TN0/FP4/FN3), below both 50% baselines. The span ranker matched AI-proposed locations on 1/4 defective test pairs. This is a failed generalization result, not a reliable defect detector; report exact denominators. The default F006 demo is a training example and genuinely ranks COBOL23/Java10, with a separately observed -100 vs100 runtime witness. Never present that demo as unseen evaluation. `backend/dev-ui/serve.mjs` serves a hash-bound aggregate `/evaluation` report without altering frozen weights or inference code; UI shows it only when model/dataset hashes match.

`code_graph.py` produces bounded heuristic operation/type/literal graphs with data/control/sequence relations. `paired_gnn.py` provides the original portable NumPy GNN plus versioned inference dispatch; `candidate_gnn.py` and `structural_cca.py` implement the v4 comparison. The active v4 regularized GNN was selected before final evaluation from four fixed paper-inspired improvements and a fresh control. The pinned 143-task benchmark retains 120 development pairs and the same 23 reserved evaluation pairs. Every model retains five actual 96-pair fold checkpoints, with 24 validation pairs per fold and no full-development refit. Checkpoints and candidates use pooled development-only Top-1, then MRR and frozen tie-breaks. The selected sequence-edge-regularized GNN uses epoch 80; separate language heads score higher on the final gallery but must not replace the CV winner based on that result. Keep related task graph components together and reuse the frozen assignments. Score a development query only with the member that excluded it, since the other four trained on it. Runtime combines member cosine scores with a fixed equal mean; concatenation divided by sqrt(5) implements that mean without averaging independently trained weights or embedding coordinates. Freeze every candidate and the winner before once-only evaluation on the 23. Every learned preprocessing statistic must fit within the corresponding 96-pair fold. All 23 were assessed in v1/v2/v3 before this user-requested comparison; results are descriptive on a reused benchmark, not pristine unforeseen evidence. Preserve all historical artifacts and original source snapshots. Keep the fixed review gate and Z3 proof semantics independent of retrieval scores.


`POST /api/matches` runs a read-only QueryBus use case through a domain-validated application port and the shared bounded Python worker. It returns ranked program candidates tied to exact source hashes and model provenance. Scores are cosine similarities, not probabilities. A trained-model result can remain `REVIEW_REQUIRED` when validation does not support automatic suggestions. An engineer explicitly confirms a Java candidate and supplies proof inputs before verification. A matching result never authorizes an edit or supplies proof premises. Keep the new matching module layered even though no matching table is persisted.

`POST /api/ai-reviews` is a separate read-only QueryBus use case in `ai-review/`, with a pure domain request/result, application engine port, strict result validator and infrastructure Python adapter. `ml_engine.ai_review` calls a configured OpenAI-compatible Chat Completions endpoint. Configuration is server-only: `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`, response format, timeout and token budget. Do not put keys in DTOs, editor configuration, model prompts, logs or responses. Sources leave the backend only on an explicit AI review request. The model has no tools and submitted code is never executed. Keep the bounded shared worker queue and provider transport limits.

AI review findings are `AI_HYPOTHESIS`, never proof or trained defect probabilities. Return exact raw-source SHA-256 hashes and server-derived one-based excerpts; raw lines split on LF without normalizing CR or Unicode. Validate structured output, spans and candidate-input JSON strictly. Candidate inputs remain `NOT_EXECUTED`, `aiIsProof` is false and `counterexamplesExecuted` is false. Missing settings return `NOT_CONFIGURED`; refusal/provider/invalid-output statuses have no findings. An analyzed empty list never means equivalence. Do not let a model response change Z3 premises, formal proof status, patch authorization or sources. No automatic translation, repair application or model-input execution is implemented. The mocked-provider end-to-end check measures integration only; no live-provider defect accuracy has been established. See `docs/ai-defect-review.md`.

The 143 upstream program pairs label whole-task correspondence, not equivalent statements, defect locations or production banking correctness. That matching model has no risk or repair head. `gnnBugRiskScore=0` is a deprecated compatibility field with `riskAssessment.status=NOT_ESTIMATED`; do not display it as low risk. `gnn_aligner.py` provides a program-level compatibility link in the verification inspection graph, not predicted paragraph/method ground truth. The obsolete node-risk evaluator was removed on the post-hackathon branch because no shipped model implements its task. The separately trained synthetic classifier/ranker uses its own response and weights.

`cpg_builder.py` retains a separate line-oriented inspection graph. `z3_formal_prover.py` uses its own closed parser and recognized source semantics for every mathematical claim. Neural matching never prunes inputs, narrows bounds, substitutes a rate or changes proof status. Never infer successful verification from filenames, model confidence or the presence of BigDecimal. Unsupported statements/side effects and external CICS/JCL state remain UNKNOWN.

External stdin/API verification requires explicit `proofInputs`: COBOL source format, amount/rate/result field names, Java parameter names, cent bounds, and exact reference-rate pair/source/collection date. Missing or mismatched inputs must return `UNKNOWN_HALTED_LIMIT`; never substitute another rate. `FREE` and a restricted fixed-reference normalizer are supported; continuation/debug lines and other compiler features remain unsupported. Seed proof scopes retain the explicit input contract.

API routes are available without credentials or role checks. Analysis uses a bounded in-process asynchronous queue; it is not durable. List reads are paginated. Do not describe the queue as restart-safe until durable job persistence is implemented.

`UNSAT_PROVEN_SAFE` means equivalence **only for the recorded `proofScope`**, including input bounds, arithmetic/rounding semantics, supported operations and fixed reference rates. It does not establish full COBOL/Java language equivalence or production banking safety. `SAT_COUNTEREXAMPLE_FOUND` requires a concrete reproducible witness. `UNKNOWN_HALTED_LIMIT` is a normal honest result. Proposed fixes must preserve the modeled COBOL behavior, including width truncation and paragraph fall-through when present.

Report actual retrieval metrics and denominators from the versioned training/stress reports. A controlled anonymized-name stress test is not a new independent holdout. Financial-domain reliability, exact localization, and production safety remain unvalidated. Do not advertise unmeasured accuracy or latency. Keep model, dataset, split and report hashes visible.

## Validation

The VS Code extension is a thin desktop client for the existing local API. It reads only explicitly selected editor documents, including unsaved text; sends code only on an explicit matching, verification or AI review action; and never holds provider credentials or executes submitted source. AI review calls the local backend, which sends the exact pair to the configured model provider. Its separate review state must be invalidated on document versions, selection, endpoint, context or source-format changes; source-linked model findings remain hypotheses. Keep its webview passive, use a strict CSP, and render response/source text as text. Proof-input mappings and source SHA-256 hashes bind a result to a precise question. Editing source, mappings or the endpoint invalidates previous results and diagnostics. Candidate ranking reads only explicitly selected unsaved documents; confirmation rechecks hashes, text, endpoint and source format and selects only a URI. It does not apply Java edits or silently infer the proof contract. Applying a candidate requires a fresh supported, bounded UNSAT result for the exact current documents, followed by a version-aware native editor edit. Leave the edit unsaved and undoable. Diagnostics identify program-level findings; do not claim that a first-line report anchor identifies the defect location. The extension has its own unit and native-host tests; the server architecture rules remain unchanged.

Keep generated VSIX files, dependency installs, extension-host profiles and compiled output out of Git. The extension package is not a Marketplace publication.
